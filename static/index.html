INSIDE THE SCHEDULING ALGORITHM

A constraint satisfaction model

OR-Tools CP-SAT uses yes/no decisions for each course and its section bundle. A selected course must have exactly one complete bundle.

Select a course = select one valid section bundle

Hard constraints: every plan must fit

  • Course count, credit range and must-take courses.
  • Completed prerequisites and any minimum grades; explicit corequisites can be taken together.
  • Available times and conflicts checked by weekday and actual section dates.
  • Required class components, cross-listing duplicates and published forbidden course overlaps.

Different objectives create different families

The first plan prioritizes career relevance, then fewer campus days and less early class time. Other anchors emphasize foundations or subject breadth.

Quality ≥ 85% of the best-found career score
For a 4-course plan: replace at least 2 courses between families

Variants stay close to their family

Keep the highest-priority n − 1 courses as a shared core. Change sections or at most one elective. Collapse identical timetables and duplicate course sets.

Same core + section changes / one elective swap

A bounded, inspectable search

Up to 45 eligible courses and 80 bundles per course enter the model. Each objective gets 4 seconds; the agent can search at most twice. Results expose coverage, exclusions and solver status.

“Optimal” applies to the stated objective and candidate pool. Source ambiguities go to review; the university confirms final enrollment eligibility.
